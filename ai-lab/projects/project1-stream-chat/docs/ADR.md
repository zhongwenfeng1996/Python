# 架构决策记录（ADR）

> 每个关键技术选择写清楚：**选了什么、放弃了什么、为什么、代价是什么**。
> 面试时 80% 的深挖都发生在这里 —— 能讲清取舍，才说明这个决定是你做的，而不是抄的。
>
> 格式固定 5 行，不写长篇大论。新增决策往下追加，不修改历史条目
> （改了要新开一条，写清"为什么推翻"）。

---

## ADR-001 · 前端用 Vue 3 走 CDN，暂不引入构建链

**决定**：前端是单个 `index.html`，Vue 3 从 CDN 引入，不配 Vite / npm。

**放弃**：单文件组件（SFC）、TypeScript 编译期检查、热更新、生产打包体积优化。

**为什么**：本项目的验收点是"流式渲染 + 可中断 + 成本可视化"，不是"配好构建工具"。
引入构建链会让 W1 的三天里有一整天花在 webpack/vite 报错上，而学到的东西与
LLM 工程能力无关。计划 §0 的"工程 > 训练"不等于"所有工程细节都现在做"。

**代价**：① 无 TS 类型检查，前端只能靠运行时发现拼写错误；
② 产物不压缩，首屏依赖 CDN；
③ 换到 W6 补 Next.js 时要重写这一层。**这个代价是刻意接受的**：
前端的类型安全在项目二（结构化输出 + Zod）时才有真正的收益，那时再引入构建工具。

## ADR-002 · 手写 fetch + ReadableStream 解析 SSE，不用 AI SDK

**决定**：自己写 SSE 解析（含跨 chunk 的 buffer 拼接），不用 `@ai-sdk/vue` 的 `useChat`。

**放弃**：现成的流式状态管理、自动重试、消息持久化等能力。

**为什么**：计划 §0 原则 2 —— "先手写，再上框架。框架会变，概念不会变。"
`week01/chat.py` 已在服务端手写过一遍；这次在浏览器端再写一遍，
才能真正回答"TCP 分包为什么会让 `split('\n\n')` 出错"这类问题。
这些是面试里区分"用过框架"和"理解流"的地方。

**代价**：多写了约 40 行 buffer 管理代码；重连、退避、消息持久化都得自己做。
**下一步**：项目二会引入 AI SDK 对照实现一遍，并在文档里写清"框架替我做了什么"。

## ADR-003 · 后端完全无状态，对话历史由前端全量提交

**决定**：`POST /api/chat` 每次接收完整的 `messages` 数组，服务端不保存任何会话。

**放弃**：服务端会话存储、增量传输历史、服务端侧的上下文裁剪。

**为什么**：三个功能直接因此变简单 ——
"重新生成"= 前端丢掉最后一条助手消息重发；
"编辑已发消息后重跑"= 前端截断数组重发；
"清空"= 前端清空数组。
服务端不需要 session、不需要过期清理、不需要处理"用户开了两个标签页"。

**代价**：① 每轮重复传输全部历史，token 成本随轮次线性增长（长对话尤其明显）；
② 上下文裁剪逻辑落在前端，容易被绕过。
**何时推翻**：项目三（数据 Agent）必须落库保存查询历史与图表配置，
届时会引入服务端会话，并在这里补一条 ADR 说明为什么翻转。

## ADR-004 · 模型清单写在代码里，不做成配置文件

**决定**：`backend/config.py` 里的 `MODEL_REGISTRY` 是唯一的模型定义来源。

**放弃**：YAML/数据库驱动的模型配置、运行期热更新、多租户自定义模型。

**为什么**：模型清单是**部署期配置**而不是运行期数据 ——
它需要类型检查、需要和代码一起 review、需要能 diff。
放 YAML 会得到一个没有校验的字典；放数据库会让本地开发多一个依赖，
也让"我本地跑不起来"变成一个环境问题而不是代码问题。

**代价**：加模型要改代码 + 重新部署。**这在当前规模下不是问题**：
真需要多租户自定义模型时再抽出来，那时才有真实需求来指导接口设计。

## ADR-005 · 首 token 超时（8s）单独降级，而不是靠总超时

**决定**：区分两个超时 —— 首 token 超时（默认 8s，触发降级）与总超时（默认 60s，兜底）。

**放弃**：单一超时；也放弃了"无限重试直到成功"。

**为什么**：流式体验里 **TTFT（首 token 延迟）比总耗时更影响体感**。
一个 40 秒生成完但 0.5 秒就出字的回答，比 5 秒才出字的回答"感觉快"得多。
如果只用总超时，用户的等待时间会变成不可预期的 60 秒 —— 那是最糟的体验。

**代价**：① 降级要用户多等一个首 token 超时（最多 2 次降级 ≈ 16s 起），
所以候选模型**上限设为 3 个**，宁可快速失败也不无限等；
② 已经吐出内容后失败**不再降级**（否则两段不同模型的话会拼在一起），
代价是有时无法自愈。这两条都是刻意选择"可预期"而非"尽力而为"。

## ADR-006 · 测试用真进程 + 真 HTTP，不用 ASGI 内存传输

**决定**：`tests/` 用 `subprocess` 起 uvicorn 和 mock 上游，通过真实 socket 测试。

**放弃**：`httpx.ASGITransport` + `asgi-lifespan` 的内存内测试（更快、更简单）。

**为什么**：本项目有一条验收项是"**中断后不残留后台请求**"。
内存传输不经过真实 socket，客户端断开这件事根本不会发生，
这条验收项就永远测不到 —— 而它恰是最容易写错、后果最严重的一条
（生产环境表现为"用户点了停止，服务端还在为它烧 token"）。

**代价**：每个测试套件要起两个进程，13 个用例耗时约 5 秒。**这个代价可以接受**：
真实覆盖换来的信心，比 2 秒的测试执行时间值钱。

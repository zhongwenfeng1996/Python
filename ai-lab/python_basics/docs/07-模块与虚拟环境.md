# 07 · 模块、包管理与虚拟环境

> **一句话总结**：Python 里"一个文件就是一个模块"；
> 而虚拟环境是**前端最容易忽略、也最容易踩坑**的一件事。

---

## 1. import 的三种形式

```python
# 形式 1：导入整个模块，用的时候加前缀
import json
data = json.loads(text)

# 形式 2：只导入需要的东西
from pathlib import Path
p = Path("a.txt")

# 形式 3：导入并改名（避免冲突或简写）
import urllib.request as req
from datetime import datetime as dt
```

> **不要用** `from json import *`（星号导入）。
> 它会污染命名空间，让你分不清某个函数是哪来的。

### 模块名就是文件路径

```
项目结构：
myapp/
├── main.py
└── utils/
    ├── __init__.py          ← 有这个文件才算是"包"
    └── helpers.py
```

```python
# 在 main.py 里
from utils.helpers import clean_text      # 对应 utils/helpers.py 里的 clean_text
import utils.helpers                       # 导入整个模块

utils.helpers.clean_text("  x  ")          # 加前缀调用
```

对比 JS：

```javascript
import { cleanText } from "./utils/helpers.js";    // 要写相对路径和扩展名
```

> **差异**：Python 用**点号**表示目录层级，**不写 `.py`**；
> JS 用 `./` 和 `/`，通常要写扩展名。

## 2. `if __name__ == "__main__":`

你在 [`03_chunk_text.py`](../03_chunk_text.py) 末尾见过这行：

```python
if __name__ == "__main__":
    main()
```

**为什么需要它？**

Python 里每个文件都可以"被直接运行"或"被别的文件导入"：

```python
# utils.py
def clean(text):
    return text.strip()

if __name__ == "__main__":
    # 只有"直接运行 python utils.py"时才执行
    # "被 import" 时不执行
    print(clean("  hello  "))
```

```python
# main.py
from utils import clean          # 此时 utils 里的 print 不会执行
```

`__name__` 是 Python 自动设置的变量：
- 直接运行这个文件时 → `"__main__"`
- 被 import 时 → 模块名（如 `"utils"`）

> **实践规则**：所有脚本都这样写，把主逻辑放在 `main()` 函数里。
> 这样别人 import 你的代码时不会有意外的副作用（比如意外发起 API 调用）。

## 3. 标准库速查（够用版）

这些**不需要安装**，直接 import：

```python
import json          # JSON 读写            ★ 最常用
import os            # 环境变量、路径        ★
import sys           # 命令行参数、退出
import time          # sleep、计时
from pathlib import Path        # 路径操作   ★
from datetime import datetime, timedelta       # 时间   ★
import random        # 随机数
import re            # 正则表达式
import hashlib       # 哈希（做缓存 key）
import urllib.request           # 发 HTTP 请求（无依赖）
import collections   # Counter、defaultdict
```

**几个马上会用到的用法**：

```python
# os：环境变量（放 API Key）
import os
api_key = os.environ.get("OPENAI_API_KEY", "")

# datetime：时间戳、计算时间差
from datetime import datetime, timedelta
now = datetime.now()
tomorrow = now + timedelta(days=1)
print(now.isoformat())              # 2026-02-14T10:30:00

# time：计时（测 TTFT 和总耗时）
import time
start = time.time()
do_something()
print(f"耗时 {time.time() - start:.2f}s")

# random：可复现的随机（数据生成要固定 seed）
import random
rnd = random.Random(42)             # 固定 seed，结果可复现
print(rnd.choice(["a", "b", "c"]))

# collections.Counter：计数神器
from collections import Counter
words = "a b a c a".split()
print(Counter(words))               # Counter({'a': 3, 'b': 1, 'c': 1})

# hashlib：给 prompt 生成缓存 key
import hashlib
key = hashlib.md5("prompt内容".encode()).hexdigest()
```

## 4. 虚拟环境（本节最重要）

### 为什么需要它

JS 里每个项目有自己的 `node_modules/`，天然隔离。
**Python 默认装在全局**，所有项目共用一套包。

后果：
- A 项目要 `openai==1.0`，B 项目要 `openai==2.0` → 冲突
- 系统自带的 Python 包被覆盖 → 系统工具坏掉

### 正确做法

```bash
# 1. 在项目目录创建虚拟环境（只需一次）
python3 -m venv .venv

# 2. 激活（每次开新终端都要做）
source .venv/bin/activate        # macOS / Linux
# .venv\Scripts\activate         # Windows

# 激活后命令行前面会出现 (.venv)
(.venv) $ pip install httpx

# 3. 退出
deactivate
```

> **判断是否激活成功**：看命令行提示符前面有没有 `(.venv)`。
> 没有就说明你正在往全局装包。

### 包管理工具对照

| 概念 | JavaScript | Python |
|---|---|---|
| 依赖清单 | `package.json` | `pyproject.toml` 或 `requirements.txt` |
| 安装 | `npm install` | `pip install` / `uv add` |
| 锁定版本 | `package-lock.json` | `uv.lock` / `poetry.lock` |
| 隔离目录 | `node_modules/`（自动） | `.venv/`（**手动创建和激活**） |
| 运行脚本 | `npm run dev` | `python main.py` |

### 现代工具：uv（推荐）

`pip` 慢且不带锁定，现在更推荐 `uv`：

```bash
# 安装 uv（一次）
curl -LsSf https://astral.sh/uv/install.sh | sh

# 用 uv 管理项目
uv init myproject
uv add httpx pydantic          # 自动创建 .venv 并写入 pyproject.toml
uv run main.py                 # 不需要手动 activate
```

> 你现在**不需要马上用 uv**。前 3 天所有练习都是零依赖（只用标准库）。
> 等你装第一个第三方库（`httpx` 或 `pydantic`）时再回来看这一节。

### requirements.txt

传统方式，很多项目还在用：

```txt
httpx==0.27.0
pydantic>=2.0
fastapi
```

```bash
pip install -r requirements.txt
pip freeze > requirements.txt      # 导出当前环境
```

## 常见坑

| 坑 | 说明 |
|---|---|
| 没有激活虚拟环境就 `pip install` | 装到了全局，项目依赖混乱 |
| 把 `.env` 提交到 Git | 密钥泄露。`.gitignore` 必须包含 `.env` |
| `from module import *` | 污染命名空间 |
| 循环导入 | A import B，B import A → 报错。用局部导入或重构解决 |
| 文件名和标准库同名 | 自己的 `json.py` 会导致 `import json` 导入到你的文件 |
| 忘记 `if __name__ == "__main__":` | 被 import 时意外执行主逻辑 |

**3.** 问题：**你的 `json.py` 会覆盖标准库的 `json` 模块**。

Python 找模块时会先看当前目录，所以 `import json` 导入的是**你的文件**，
不是标准库。结果就是 `json.dumps` 不存在，报 `AttributeError`。

这属于"命名遮蔽"（shadowing），是 Python 新手最常见的诡异 bug 之一。

**规则**：不要用标准库名做文件名。常见要避开的：
`json.py` `random.py` `time.py` `types.py` `email.py` `logging.py` `queue.py` `select.py` `code.py` `copy.py`

判断方法：想用某个文件名时，先在心里过一遍"这会不会是标准库名字"，
或者干脆加前缀，如 `my_json_utils.py`。

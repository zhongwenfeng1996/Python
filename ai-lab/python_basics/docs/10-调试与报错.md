# 10 · 调试与报错

> **一句话总结**：读 traceback 是一项可以练的技能。学会之后，
> 90% 的报错你自己就能修，不用去搜、不用问人。

---

## 1. 怎么读 traceback

Python 报错时输出一大段，新手会慌。其实只需要看两个地方：

```text
Traceback (most recent call last):
  File "G:\转型\ai-lab\python_basics\01_hello_llm.py", line 68, in <module>
    with urllib.request.urlopen(request, timeout=60) as response:
         ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
  File "C:\Python312\Lib\urllib\request.py", line 216, in urlopen
    return opener.open(url, data, timeout)
           ^^^^^^^^^^^^^^^
  File "C:\Python312\Lib\urllib\request.py", line 519, in open
    response = self._open(req, data)
               ^^^^^^^^^^
  ...（中间还有十几行）...
  File "C:\Python312\Lib\socket.py", line 833, in create_connection
    raise err
ConnectionRefusedError: [WinError 10061] 由于目标计算机积极拒绝，无法连接。
```

> **同一段 traceback 在不同平台上长得不一样**，别因为"和教程对不上"就慌：
>
> | | 你的文件路径 | 库的路径 | 连接被拒的错误行 |
> |---|---|---|---|
> | Windows | `G:\转型\...\01_hello_llm.py` | `C:\Python312\Lib\...` | `[WinError 10061]` |
> | macOS | `/Users/you/.../01_hello_llm.py` | `/opt/homebrew/Cellar/python@3.13/...` | `[Errno 61]` |
> | Linux | `/home/you/.../01_hello_llm.py` | `/usr/lib/python3.12/...` | `[Errno 111]` |
>
> **要看的是结构，不是字面内容**：最后一行是错误类型，最上面那个"文件名是你自己写的文件"
> 的那一行，才是你的代码出问题的地方。

**只看两个地方**：

| 看哪里 | 是什么 | 上面这个例子里 |
|---|---|---|
| **最后一行** | 错误类型 + 原因 | `ConnectionRefusedError: [WinError 10061]` |
| **最上面一个属于你的文件** | 你的代码哪一行出问题 | `01_hello_llm.py, line 68` |

中间那一大堆是**库的内部调用链**，新手可以完全跳过。

### 阅读顺序

```text
1. 最后一行 → 什么错了？
   "目标计算机积极拒绝" / "Connection refused" = 连接被拒绝

2. 最上面那个你的文件 → 你哪一行触发了它？
   01_hello_llm.py 第 68 行，就是发请求那一行

3. 结论：请求发不出去，因为目标服务没在跑
   → 检查 mock server 启动了没有（以及 OPENAI_BASE_URL 的端口对不对）
```

**练习这个方法**：下次报错，先用手指按住屏幕，只看最后一行。

## 2. 常见错误速查表

看到异常名，基本就知道是什么问题了：

| 异常 | 中译 | 最常见原因 |
|---|---|---|
| `NameError` | 名字未定义 | 变量名拼错，或用了 `true` / `null`（应该是 `True` / `None`） |
| `TypeError` | 类型错误 | 字符串和数字相加；函数参数个数不对；调用了不是函数的东西 |
| `ValueError` | 值错误 | `int("abc")`；解包的元素个数不匹配 |
| `KeyError` | 键不存在 | 字典取值用了不存在的 key，改用 `.get()` |
| `IndexError` | 下标越界 | 列表取超范围，比如空列表取 `[0]` |
| `AttributeError` | 属性不存在 | `list.push()`（应该是 `append`）；`dict.name`（应该 `dict["name"]`） |
| `ModuleNotFoundError` | 模块找不到 | 没安装 / 装到了别的环境 / 文件名遮蔽 |
| `FileNotFoundError` | 文件不存在 | 路径写错；工作目录不对 |
| `IndentationError` | 缩进错误 | 混用 tab 和空格；缩进层级不一致 |
| `SyntaxError` | 语法错误 | 少写冒号、括号不匹配、中文标点 |
| `JSONDecodeError` | JSON 解析失败 | 接口返回的不是 JSON（可能是 HTML 错误页） |
| `ConnectionRefusedError` | 连接被拒绝 | 服务没启动；端口不对 |
| `UnboundLocalError` | 局部变量未绑定 | 函数内给全局变量赋值却没写 `global` |
| `RuntimeWarning: coroutine 'xxx' was never awaited` | 协程没被 await | 忘记写 `await`（第 09 章） |

### 三个最容易困惑的

**`SyntaxError` 里提示的行号可能是错的**

```python
print("hello"
print("world")
```
报错可能指向第 2 行，但问题在第 1 行（少了右括号）。
**规则**：`SyntaxError` 报的行号，往上多看一两行。

**`IndentationError` 常常看不见**

tab 和空格长得一样。解决方法：编辑器设置"tab 转 4 空格"，
并打开"显示空白字符"。

**中文标点**

```python
# ❌ 下面这行的引号是全角（中文）引号，Python 不认识
print(“hello”)
```

报错长这样（注意 `U+201C` 这个码点，它直接告诉你问题在哪）：

```
SyntaxError: invalid character '“' (U+201C)
```

从网页或文档复制代码时最容易发生。**别用眼睛分辨全角半角**（多数编辑器里几乎分不出来），
直接搜全角字符类 `[“”‘’：，（）]`。
其中全角冒号 `：` 最隐蔽 —— 它只在 `def` / `if` 那一行报错，而那一行"看起来完全正常"。

## 3. 代码不报错，但结果不对

这类问题最难查。三个方法：

### 方法 1：缩小范围（二分法）

```python
# 先怀疑数据，还是怀疑逻辑？
print(f"输入数据: {data[:200]}")       # 数据对不对？
print(f"长度: {len(data)}")
print(f"类型: {type(data)}")
print(f"第一步结果: {result}")          # 逻辑对不对？
```

### 方法 2：打印中间态（LLM 应用必备）

```python
def call_model(messages):
    print(f"[DEBUG] 发送 {len(messages)} 条消息")
    print(f"[DEBUG] 最后一条: {messages[-1]}")
    response = request(...)
    print(f"[DEBUG] 响应状态: {response.status}")
    print(f"[DEBUG] 原始响应: {response.text[:200]}")
    return response
```

> **在 LLM 应用里，`print` 调试是主力手段**。
> 因为问题往往出在"模型收到了什么"和"模型返回了什么"，
> 把这两样打出来，80% 的问题一目了然。

### 方法 3：断言（把假设写下来）

```python
def parse(response):
    assert isinstance(response, dict), f"响应应该是字典，实际是 {type(response)}"
    assert "choices" in response, f"响应缺少 choices: {response.keys()}"
    choices = response["choices"]
    assert len(choices) > 0, "choices 是空的"
    return choices[0]["message"]["content"]
```

断言失败时会打印你写的消息，比 `KeyError` 清楚得多。

## 4. 让 AI 帮你读报错（正确姿势）

你正在用 AI 学习，但**怎么问**决定了它能不能帮上忙。

### ❌ 差的问法

> 我代码报错了，怎么改？

AI 只能猜，大概率给你一段不相关的通用建议。

### ✅ 好的问法（四要素）

```
1. 我想做什么：（一句话）
2. 完整报错：（整段 traceback，不要截断最后一行）
3. 相关代码：（出错的那个函数，不用贴整个文件）
4. 我已经试过：（你排查过什么）
```

实例：

> **想做什么**：用 mock server 测试 01_hello_llm.py
> **报错**：
> ```
> Traceback (most recent call last):
>   File "01_hello_llm.py", line 68, in <module>
>     with urllib.request.urlopen(request, timeout=60) as response:
> ConnectionRefusedError: [WinError 10061] 由于目标计算机积极拒绝，无法连接。
> ```
> **相关代码**：第 68 行是发请求，BASE_URL 从环境变量读，我设的是
> `http://127.0.0.1:8765/v1`
> **已试过**：确认 mock_server.py 那个终端没关，但可能是端口被我另一个程序占了

这样问，AI 能直接定位问题。

### 更重要的原则

**先自己读最后一行**，再去问。原因不是"要独立思考"，
而是**读最后一行只需要 10 秒，而你描述问题给 AI 要 2 分钟**。

读不出来再去问，并且把 traceback 完整贴出来。

## 6. 一个真实的调试过程

假设你在跑 `02_stream_chat.py`，输出是这样的：

```
你: 你好
AI: 
对话结束，共 1 轮
```

**没有报错，但没有回复。** 怎么查？

```text
第 1 步：现象是什么？
  → AI 没有输出任何内容，程序正常结束

第 2 步：可能是哪几个环节出问题？
  ① 请求没发出去
  ② 发出去了但响应是空的
  ③ 响应有内容但解析逻辑没提取出来
  ④ 提取出来了但没打印

第 3 步：用 print 定位到具体环节
  在 ask_model 里加：
    print(f"[DEBUG] full_text = {full_text!r}")
  结果输出 full_text = ''  → 说明是 ① 或 ② 或 ③

  再加：
    print(f"[DEBUG] chunk = {chunk}")
  一次都没打印 → 说明 for 循环没进入 → 是 ① 或 ②

  再加：
    print(f"[DEBUG] 响应状态 = {response.status}")
  打印出 200 → 请求成功，是解析问题

第 4 步：对比 mock 返回的格式和自己代码的判断条件
  mock 返回的每行是：data: {"choices": [...]}
  代码判断的是：line.startswith("data:")
  ...
  发现：line 是 bytes，没 decode 就直接 startswith("data:")，
       bytes.startswith(str) 会 TypeError...

  （实际上会报错，所以更常见的情况是：判断条件写成了 "data: " 带空格）
```

**这个过程的重点不是结论，而是方法**：
**把"没输出"这个模糊现象，一步步缩小到一个具体的位置。**

## 7. 在 AI 应用里：LLM 的报错和普通 Web 有什么不同

前面六节讲的是通用的调试方法。这一节补一个**你在普通后端不会遇到**的情况。

> 本节只讲"差异在哪"，涉及的具体写法（`response.json()`、`raise_for_status()` 等）
> 分别在[附录 A](附-A-读懂一次模型API调用.md) 和第 06 章，现在看个意思就行。

**区别 1：一半的"报错"根本不是异常**

普通后端：出问题 → 抛异常 → 看 traceback。

LLM 应用：请求返回 **200**，但内容可能是
"抱歉，我无法回答这个问题"、字段名从 `company` 变成了 `Company`、
或者 JSON 外面裹了一层 ` ```json `。
**这些都不抛异常 —— 你的代码"成功地"拿到了一堆错东西。**

所以调试重心从"读 traceback"部分转移到**"在关键位置留下检查"**：
拿到模型输出后，先确认它不是空的、格式没变，再往下用。

**区别 2：错误往往在"上游"而不在你的代码里**

数据流是四层：**你的代码 → HTTP → 模型服务 → 模型本身**。
任何一层都能出问题，而且症状很像：

| 层 | 典型症状 | 怎么确认 |
|---|---|---|
| 你的代码 | 拼错 key、忘了 `await`、`encoding` 不对 | traceback 指向你的文件 |
| HTTP / 网络 | 401 / 429 / 超时 / 代理拦截 | 看状态码 + **把响应体打出来** |
| 模型服务 | 500、模型名不存在、额度用完 | 响应体里通常有 `error.message` |
| 模型本身 | 200 但答非所问、JSON 不合法、拒绝回答 | 只能靠评估，不是靠调试 |

**排查顺序很重要**（RAG 效果不好时同样适用）：

> 先确认**请求发了什么** → 再确认**返回的原文是什么** → 最后才怀疑解析逻辑。

大部分"模型不听话"的问题，卡在第二步：**只看解析后的结果，没看原始响应。**

> 这个"四层"的视角在项目里会更明显：项目一 `providers.py` 里
> 每一层都有独立的错误处理（连接失败 / HTTP 错误 / 首 token 超时 / 解析失败），
> 就是为了让"哪一层出问题"一眼可见。

**区别 3：成本相关的错误是静默的**

上下文拼错了不会报错，只会让你多花 10 倍的钱。所以调试 LLM 应用时，
**token 数和耗时也要当成一等公民记录下来**（`week01/chat.py` 就是这么做的）。

> 这一章的"读 traceback"依然是基本功，但在 LLM 应用里，
> 更值钱的技能是**设计让错误可见的日志与断言**。

## 8. 常见坑

| 坑 | 症状 | 正确做法 |
|---|---|---|
| 只看最后一行就动手 | 改了错的地方，问题还在 | 最后一行看**类型**，你的文件那一行看**位置**，两个都要 |
| 用 `except Exception: pass` 兜住 | 程序"正常"，但结果全空 | 至少 `print` 或 `logging.exception` 出来 |
| 把 traceback 截断后去问 AI | 得到泛泛而谈的答案 | 完整贴，最后一行和你的文件那一行最关键 |
| 改了代码但跑的是旧进程 | 改了没生效，怀疑人生 | 确认没有残留进程 / 缓存；Python 脚本一般无缓存问题，注意 `.pyc` 与 `__pycache__` |
| 中文乱码当成"程序错了" | 实际是控制台编码不是 UTF-8 | 见 [Windows 上手指南](../../../ai-lab/docs/windows-quickstart.md)；代码里显式 `encoding="utf-8"` |
| 用 `print` 打印 `bytes` | 看到 `b'data: {...}'` | 先 `decode("utf-8")` 再判断，`startswith` 对 str 和 bytes 不通用 |
| 把"模型答得不好"当 bug 调 | 花几小时改代码，其实是提示词问题 | 先看响应原文，再判断是解析问题还是模型问题 |
| Windows 上看不到报错全文 | 输出被截断 | 重定向到文件再读：`py -3 a.py > out.txt 2>&1` |

## 练习

**1.** 下面报错的原因是什么？（只看最后一行就能答）

```
Traceback (most recent call last):
  File "test.py", line 3, in <module>
    print(user["email"])
KeyError: 'email'
```

**2.** 下面代码报什么错？为什么？改怎么改？

```python
response = {"choices": []}
content = response["choices"][0]["message"]["content"]
```

**3.** 你的代码输出是空的，但没有任何报错。
写出你的三步排查计划（具体要 print 什么）。

<details>
<summary>参考答案</summary>

**1.** 字典 `user` 里没有 `email` 这个 key。

两种改法：

```python
# 给默认值
email = user.get("email", "")

# 或者判断后再用
if "email" in user:
    print(user["email"])
```

**2.** 报 `IndexError: list index out of range`。

原因：`response["choices"]` 是**空列表**，`[0]` 取不到东西。
（如果连 `choices` 都没有，会先报 `KeyError`。）

改法：

```python
choices = response.get("choices") or []
if not choices:
    print("响应里没有 choices，可能是接口报错了")
    content = ""
else:
    content = choices[0].get("message", {}).get("content", "")
```

**3.** 三步排查计划：

```python
# 第 1 步：确认输入对不对
print(f"[1] 输入长度={len(text)}, 内容={text[:50]!r}")

# 第 2 步：确认核心处理逻辑有没有产出
result = process(text)
print(f"[2] 处理结果={result!r}, 类型={type(result)}")

# 第 3 步：确认输出环节
print(f"[3] 准备输出 {len(items)} 项")
for item in items:
    print(item)
```

思路：**沿着数据流，从输入到输出逐段打印**，
找到第一个"不该为空却为空"的位置，问题就在它前面一步。

> 注意用 `!r`（repr）打印：空字符串和空格字符串在普通 print 里看起来一样，
> 但 `''` 和 `' '` 在 repr 下一目了然。

</details>

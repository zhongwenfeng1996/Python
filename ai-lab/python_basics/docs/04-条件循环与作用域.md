# 04 · 条件、循环与作用域

> **一句话总结**：语法比 JS 更简单，但**作用域规则不同**——Python 没有块级作用域，
> 循环变量会泄漏到外面。

---

## 1. 条件判断

```python
score = 85

if score >= 90:
    print("优秀")
elif score >= 60:        # 不是 else if
    print("及格")
else:
    print("不及格")
```

对比 JS：

```javascript
if (score >= 90) {
  console.log("优秀");
} else if (score >= 60) {
  console.log("及格");
} else {
  console.log("不及格");
}
```

三个差异：

| | JS | Python |
|---|---|---|
| 条件括号 | `if (x > 1)` | `if x > 1:` |
| 代码块 | `{ }` | **缩进**（4 个空格） |
| 逻辑运算 | `&&` `\|\|` `!` | `and` `or` `not` |

```python
# 逻辑运算
if score >= 60 and not is_absent:
    print("通过")

if is_admin or is_owner:
    print("有权限")

# 三元表达式（顺序和 JS 相反！）
status = "成年" if age >= 18 else "未成年"
# JS: const status = age >= 18 ? "成年" : "未成年";
```

> **缩进就是语法**。JS 缩进错了只是难看，Python 缩进错了直接报
> `IndentationError`。编辑器里请打开"显示空白字符"。

## 2. `in` 运算符：比 JS 好用

```python
# 判断成员
if "login" in event_types:
    print("包含 login")

if "key" in my_dict:            # 判断字典的 key
    print("有这个 key")

if "错误" in text:               # 子串判断（JS 是 includes）
    print("文本包含'错误'")
```

## 3. 循环

### for 循环：直接遍历元素

```python
# JS: for (const item of items)
for item in items:
    print(item)

# 遍历字符串
for ch in "abc":
    print(ch)

# 遍历字典
for key in my_dict:
    print(key)
```

### range：生成数字序列

```python
for i in range(5):          # 0, 1, 2, 3, 4
    print(i)

for i in range(1, 5):       # 1, 2, 3, 4（含头不含尾）
    print(i)

for i in range(0, 10, 2):   # 0, 2, 4, 6, 8
    print(i)

# 倒序
for i in range(5, 0, -1):   # 5, 4, 3, 2, 1
    print(i)
```

> `range(5)` **不包含 5**。这个"含头不含尾"的规则和切片一致，
> 是整个 Python 的统一约定。

### enumerate：同时拿下标和元素

```python
names = ["Alice", "Bob", "Carol"]

for i, name in enumerate(names):
    print(f"{i}: {name}")
# 0: Alice
# 1: Bob
# 2: Carol

# 想从 1 开始编号
for i, name in enumerate(names, start=1):
    print(f"第{i}名：{name}")
```

对比 JS：`names.entries()` 或 `forEach((name, i) => ...)`。

### zip：并行遍历多个列表

```python
names = ["Alice", "Bob"]
ages = [25, 30]

for name, age in zip(names, ages):
    print(f"{name} 今年 {age} 岁")
```

### while 循环

```python
count = 0
while count < 3:
    print(count)
    count += 1          # Python 没有 count++ ！
```

> **前端注意**：Python **没有 `++` 和 `--`**，要写 `count += 1`。

### break 和 continue

```python
for i in range(10):
    if i == 3:
        continue        # 跳过本次，继续下一次
    if i == 6:
        break           # 跳出整个循环
    print(i)            # 输出 0 1 2 4 5
```

### for-else（Python 独有，很好用）

```python
for item in items:
    if item == target:
        print("找到了")
        break
else:
    print("循环正常结束（没 break）→ 没找到")
```

`else` 在循环**没有被 break 打断**时执行。这在"查找失败要处理"的场景里很优雅。

## 4. 作用域（本节最容易踩坑）

### Python 没有块级作用域

```python
# JS
for (let i = 0; i < 3; i++) {}
// console.log(i);   // ❌ ReferenceError: i is not defined

# Python
for i in range(3):
    pass
print(i)              # ✅ 2 —— i 还在！
```

```python
if True:
    x = 10
print(x)              # ✅ 10 —— if 块里定义的变量外面也能用
```

> **这是前端最容易踩的坑**：Python 只有**函数级作用域**，没有块级作用域。
> 循环变量、if 块里的变量都会留在外面。
>
> 实际影响：不要用 `i`、`x`、`temp` 这类短名字，
> 否则后面的代码可能意外用到前面的残留值。

### 函数内部访问全局变量

```python
count = 0

def increment():
    # count += 1        # ❌ UnboundLocalError
    global count        # 声明"我要改的是全局的 count"
    count += 1

increment()
print(count)            # 1
```

> **建议**：尽量不用 `global`。需要修改外部状态时，
> 用参数传入、用返回值传出，代码会清晰得多。

### 函数内部可以**读**全局变量

```python
API_KEY = "sk-xxx"

def call_api():
    print(API_KEY)      # ✅ 读取没问题，不需要 global
```

## 在 AI 应用里，它出现在哪

```python
# 1. 重试循环（最常见的模式）
max_retries = 3
for attempt in range(max_retries):
    try:
        result = call_model(prompt)
        break                       # 成功就跳出
    except Exception as e:
        print(f"第 {attempt + 1} 次失败：{e}")
else:
    print("重试全部失败")            # for-else：没 break 说明全失败

# 2. 遍历对话历史做上下文压缩
for i, msg in enumerate(messages):
    if i < len(messages) - 10:      # 只保留最近 10 条
        continue
    print(msg["content"])

# 3. 条件分支处理不同响应
if usage is None:
    tokens = estimate_tokens(text)
else:
    tokens = usage["completion_tokens"]

# 4. 流式解析里的循环 + break
#    （response 是 urlopen 的返回值；详见下方"关于第 4 条的坑"）
with urllib.request.urlopen(request, timeout=60) as response:
    for raw_line in response:
        if raw_line.strip() == b"data: [DONE]":
            break                       # 遇到结束标记就停
        if not raw_line.startswith(b"data:"):
            continue                    # 跳过无关行
        chunk = json.loads(raw_line[5:])

# 5. 循环变量泄漏的真实影响
for i, item in enumerate(items):
    process(item)
print(i)          # 循环结束后 i 仍然存在，值是最后一个下标
```

### 关于第 4 条的坑：bytes 和 str 不能混着比

上面第 4 条里我写的是 `raw_line`（字节）配 `b"..."`（字节字面量），
而不是 `line`（字符串）配 `"..."`。**这个区别很容易被忽略：**

```python
for raw_line in response:
    if raw_line.strip() == "data: [DONE]":     # ← 静默失效
        break
    if not raw_line.startswith("data:"):       # ← 会抛 TypeError
        continue
```

实测这两个失败方式**不一样**，值得分清（`python3 week01/probe_iteration.py` 可复现）：

| 写法 | 结果 | 能发现吗 |
|---|---|---|
| `b'data: [DONE]'.strip() == "data: [DONE]"` | **`False`** | ❌ **不报错**，静默失效 |
| `b'data: x'.startswith("data:")` | `TypeError: startswith first arg must be bytes or a tuple of bytes, not str` | ✅ 会抛错 |

**所以真正的陷阱是第一条**：`break` 永远不触发（因为结束标记永远判不出来），
循环会一直读到流结束。而 `startswith` 那条至少会炸给你看。

**正确写法二选一**：全部用字节（`b"data:"`），或先解码再全部用字符串：

```python
for raw_line in response:
    line = raw_line.decode("utf-8").strip()    # ★ 先变成 str，之后按字符串处理
    if line == "data: [DONE]":
        break
    if not line.startswith("data:"):
        continue
    chunk = json.loads(line[5:])
```

> 推荐**第二种（先 decode）**：后面 `json.loads` 本来就要字符串，
> 中文还要处理编码。少一层 bytes/str 的心智负担。
>
> **补充一个实测结论**：`urlopen` 迭代出来的是**按行切好的 bytes**
> （每行不含末尾的 `\n` 之外的内容，空行也会单独返回一条 `b'\n'`）——
> 但这是 urllib 帮我们做的包装。socket 层面拿到的是任意长度的分块，
> 所以浏览器端手写 fetch 时必须自己处理"半个 JSON"（见项目一的 `parseSSE`）。
>
> 这类"不报错但行为全错"的 bug 最难查，
> 排查方法见 [第 10 章](10-调试与报错.md) 的「代码不报错，但结果不对」。

## 常见坑

| 坑 | 说明 |
|---|---|
| `if (x > 1)` | Python 不需要括号，写成 `if x > 1:` |
| `x++` | Python 没有自增，用 `x += 1` |
| `&&` `\|\|` `!` | 要写 `and` `or` `not` |
| 缩进不一致 | 混用 tab 和空格会报错，统一用 4 个空格 |
| 循环变量泄漏 | `for i in ...` 之后 `i` 还在，别复用短变量名 |
| `range(5)` 以为到 5 | 实际是 0–4 |
| 三元表达式顺序 | `a if cond else b`，条件在中间 |

**3.** 报 `UnboundLocalError`。

原因：函数内部对 `total` 有**赋值操作**（`total += i`），
Python 会把 `total` 视为局部变量，但它在赋值前被读取了。

两种改法：

```python
# 改法 A：用参数传入、返回值传出（推荐）
def add_up():
    total = 0                 # 在函数内部初始化
    for i in range(1, 6):
        total += i
    return total

print(add_up())               # 15
```

```python
# 改法 B：声明 global（不推荐，但要知道）
total = 0

def add_up():
    global total
    for i in range(1, 6):
        total += i
    return total
```

> **推荐改法 A**。函数不依赖、不修改外部状态，是更可靠的写法——
> 这在后面写可测试的评估脚本时很重要。

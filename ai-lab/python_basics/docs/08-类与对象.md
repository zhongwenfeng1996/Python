# 08 · 类与对象

> **一句话总结**：你不需要成为 OOP 高手，但**必须能读懂 Pydantic 模型**——
> 因为 AI 应用里所有的数据结构定义都用它。

---

## 1. 为什么需要类

先看不用类的写法：

```python
def create_user(name, age):
    return {"name": name, "age": age}

def get_display_name(user):
    return user["name"]

user = create_user("Alice", 25)
print(get_display_name(user))
```

问题：
- 字段名靠字符串，拼错了要到运行时才发现（`user["nmae"]`）
- 没有"这个数据结构应该长什么样"的定义
- 无法附带校验逻辑

用类的写法：

```python
class User:
    def __init__(self, name, age):
        self.name = name
        self.age = age

    def display_name(self):
        return self.name

user = User("Alice", 25)
print(user.display_name())
print(user.name)          # 属性访问，拼错立刻报错
```

## 2. 基础语法

```python
class User:
    # __init__ 是构造方法（相当于 JS 的 constructor）
    def __init__(self, name, age):
        self.name = name        # self 就是 JS 里的 this，但必须显式写
        self.age = age

    # 方法：第一个参数永远是 self
    def greet(self):
        return f"你好，我是 {self.name}"

    def is_adult(self):
        return self.age >= 18


user = User("Alice", 25)       # 创建实例（不需要 new 关键字）
print(user.greet())            # 你好，我是 Alice
print(user.is_adult())         # True
```

对比 JS：

```javascript
class User {
  constructor(name, age) {
    this.name = name;          // JS 的 this 自动绑定
    this.age = age;
  }
  greet() {
    return `你好，我是 ${this.name}`;
  }
}
const user = new User("Alice", 25);      // JS 要 new
```

**三个差异**：
1. Python 不需要 `new`
2. Python 的方法第一个参数必须写 `self`（JS 的 `this` 是隐式的）
3. Python 没有 `private` 关键字（靠 `_name` 下划线约定）

## 3. `__repr__`：让打印好看

```python
class Message:
    def __init__(self, role, content):
        self.role = role
        self.content = content

    def __repr__(self):
        return f"Message(role={self.role!r}, content={self.content[:20]!r})"

msg = Message("user", "这是一段很长的用户消息内容")
print(msg)     # Message(role='user', content='这是一段很长的用户消息内容')
```

没有 `__repr__` 时打印出来是 `<__main__.Message object at 0x10a2b3c4d>`，
调试时完全没用。

> `!r` 表示用 `repr()` 格式化（字符串会带引号），调试时更清楚。

## 4. dataclass：最实用的类写法

手写 `__init__` 太啰嗦。`dataclass` 装饰器自动生成：

```python
from dataclasses import dataclass

@dataclass
class Message:
    role: str
    content: str
    tokens: int = 0            # 有默认值的字段放后面

msg = Message("user", "你好")
print(msg)                     # Message(role='user', content='你好', tokens=0)
print(msg.role)                # user

# 自动生成的功能：
msg2 = Message("user", "你好")
print(msg == msg2)             # True —— 自动实现了相等比较
```

> **`@dataclass` 是"数据类"的标准写法**：只用来装数据，不带复杂逻辑。
> 这是理解 Pydantic 的关键前置知识。
>
> 那个 `@` 是**装饰器**——想搞清楚它到底是什么、为什么这么写，
> 去 [附录 B：装饰器、生成器与类型注解](附-B-装饰器生成器与类型注解.md)。
> 本章先照抄 `@dataclass` 就行，不用现在弄懂它。

**dataclass + 类型注解**：

```python
from dataclasses import dataclass, field

@dataclass
class Usage:
    prompt_tokens: int
    completion_tokens: int

    @property
    def total(self):
        return self.prompt_tokens + self.completion_tokens

@dataclass
class Response:
    content: str
    usage: Usage
    model: str = "unknown"

usage = Usage(prompt_tokens=14, completion_tokens=38)
resp = Response(content="你好", usage=usage, model="deepseek-chat")

print(resp.usage.total)        # 52
print(resp.model)              # deepseek-chat
```

> **注意**：这些类型注解（`: str`、`: int`）**运行时不检查**！
> 传错类型不会报错。这正是 Pydantic 要解决的问题 ↓

## 5. 继承（了解即可）

```python
class Animal:
    def __init__(self, name):
        self.name = name

    def speak(self):
        return "..."

class Dog(Animal):
    def speak(self):                    # 重写父类方法
        return "汪汪"

class Cat(Animal):
    def speak(self):
        return "喵"

for animal in [Dog("旺财"), Cat("咪咪")]:
    print(f"{animal.name}: {animal.speak()}")
# 旺财: 汪汪
# 咪咪: 喵
```

```python
# 调用父类方法：`super().speak()` 相当于 JS 的 `super.speak()`
class Animal:
    def __init__(self, name):
        self.name = name

    def speak(self):
        return "……"


class Dog(Animal):
    def speak(self):
        parent = super().speak()          # 先拿父类的实现
        return f"{parent} 汪汪"


print(Dog("旺财").speak())                # …… 汪汪
```

> 这里把 `Animal` 又写了一遍，是为了让这一段**能单独跑**。
> 教程里每个示例都自带它需要的东西 —— 有脚本在检查这一条
> （`backend/tools/audit_code_blocks.py` 与 `run_doc_examples.py`）。

## 6. 在 AI 应用里：Pydantic 模型

**这是本节存在的真正理由。**

回忆第 01 章和第 05 章的两个事实：
1. Python 的类型注解**运行时完全不检查**
2. `dataclass` 提供了结构，但不做数据校验

所以在 AI 应用里，我们需要一个能**在运行时校验**的模型 —— 这就是 **Pydantic**。

```python
from pydantic import BaseModel, Field

class AnalysisRequest(BaseModel):
    question: str = Field(..., min_length=1, description="分析问题")
    tenant_id: int = Field(..., gt=0)
    max_rows: int = Field(default=1000, le=10000)

# 正确使用
req = AnalysisRequest(question="上月活跃用户", tenant_id=3)
print(req.max_rows)        # 1000

# 校验失败 —— 这就是 Pydantic 的价值
try:
    AnalysisRequest(question="", tenant_id=-1)
except Exception as e:
    print(e)
    # 2 validation errors for AnalysisRequest
    # question
    #   String should have at least 1 character
    # tenant_id
    #   Input should be greater than 0
```

**Pydantic 能做的事**：

```python
from typing import Literal

from pydantic import BaseModel


class ToolCall(BaseModel):
    # 枚举限定：只能是这两个值之一
    name: Literal["search", "query_db"]
    arguments: dict


class ModelOutput(BaseModel):
    # ① 没有默认值 → **必填**。少传或传 None 都会报错
    answer: str
    # ② 有默认值 → **可选**。不传就用 0.0
    confidence: float = 0.0
    # ③ 列表字段的默认值：用 `= []` 看着方便，但它是**可变默认值**，
    #    经典陷阱（第 04 章讲过 `history=[]` 那个坑）。
    #    Pydantic 会替每个实例深拷贝一份，所以**这里是安全的** ——
    #    但要知道"为什么安全"，别把习惯带回到普通函数里。
    sources: list[str] = []
    # ④ 嵌套模型 + 可为 null：`ToolCall | None` 只说明**值可以是 null**，
    #    真正让它"可选"的是后面的 `= None`。两者缺一不可。
    tool_call: ToolCall | None = None


# 从 JSON 字符串直接解析（大模型最常返回的东西）
raw = '{"answer": "42", "sources": ["doc1.pdf"]}'
output = ModelOutput.model_validate_json(raw)
print(output.answer)          # 42
print(output.confidence)      # 0.0     ← 没传，用了默认值
print(output.tool_call)       # None    ← 没传，用了默认值
```

### 必填还是可选，只看一件事：**有没有 `= 默认值`**

这是最容易混的地方，所以单独列一张表：

| 写法 | 必填？ | 能不能传 `null`？ | 说明 |
|---|---|---|---|
| `name: str` | **必填** | ❌ 不能 | 没有默认值 |
| `name: str = "x"` | 可选 | ❌ 不能 | 有默认值，但不能是 None |
| `name: str \| None` | **必填** | ✅ 能 | **类型允许 None，但字段仍然必填** ⚠️ |
| `name: str \| None = None` | 可选 | ✅ 能 | 类型允许 + 有默认值 = 真正可选 |

> ⚠️ **`str | None` 不等于"可选字段"** —— 它只放宽了**类型**，
> 字段本身还是必填。必须再给它一个默认值（通常是 `= None`）才可选。
> 这是新手最常踩的一个，也是这段代码想强调的。

### 无默认值的字段，少传会怎样？

```python
from pydantic import BaseModel, ValidationError   # ← ValidationError 必须一起 import


class ModelOutput(BaseModel):
    answer: str                       # 必填
    confidence: float = 0.0           # 可选


# answer 是必填，这里故意不传 —— 会抛 ValidationError
try:
    ModelOutput(confidence=0.5)
except ValidationError as e:
    print(e)
    # 1 validation error for ModelOutput
    # answer
    #   Field required [type=missing, input_value={'confidence': 0.5}, ...]
```

> 报错信息会**精确指到字段名与原因**（`answer` / `Field required`），
> 这正是 Pydantic 比手写校验强的地方 —— 结构化，不需要解析字符串。
>
> ⚠️ 注意这个代码块**重新定义了 `ModelOutput`**，而不是复用上面那个。
> 教程里每个示例都**自带它需要的东西**，就是为了让你能直接复制运行 ——
> 如果一个块用了另一个块里定义的类，单独跑就会 `NameError`。
> 这是本教程给自己定的规矩（有一个脚本在检查它）。


**为什么它在 LLM 应用里是核心**：

```python
import json

from pydantic import BaseModel, ValidationError   # ← ValidationError 必须一起 import


class Extracted(BaseModel):
    name: str
    email: str                                    # 必填
    company: str | None = None


# model_output 就是"模型返回的那段原始字符串" —— 通常是一段 JSON，
# 但不保证合法、也不保证字段齐全。这就是所有麻烦的来源。
model_output = '{"name": "张三"}'

try:
    data = Extracted.model_validate_json(model_output)
    print("解析成功：", data)
except ValidationError as e:
    # e 里有精确的字段级错误，可以直接拼进下一次 prompt
    retry_prompt = f"你的输出有以下错误，请修正：\n{e}"
    print(retry_prompt)
```

跑出来是这样（pydantic 2.13.5 实测）：

```
你的输出有以下错误，请修正：
1 validation error for Extracted
email
  Field required [type=missing, input_value={'name': '张三'}, input_type=dict]
    For further information visit https://errors.pydantic.dev/2.13/v/missing
```

> **注意这里发生了什么**：模型漏了 `email`（必填），
> pydantic 不但拒绝了它，还**指出缺哪个字段、为什么缺**。
> 把这整段拼回下一次 prompt，模型就有机会自己改对 ——
> 这就是"**校验失败 → 错误喂回模型 → 重试**"的闭环。

> `ValidationError` 是 pydantic 自己的异常类，**不是内建的**。
> 只写 `from pydantic import BaseModel` 然后在 `except` 里用它，
> 会得到 `NameError: name 'ValidationError' is not defined` ——
> 而且它只在"模型恰好返回了非法内容"这条路径上才炸，平时测试发现不了。

### 那段错误信息里的文档 URL 很浪费 token —— 但"改用结构化"不一定省

实测（同一段代码，见 `backend/tools/show_pydantic_errors.py`）：

| 写法 | 长度 |
|---|---|
| `str(e)` | 192 字符 |
| `json.dumps(e.errors())` | **142** 字符 ← 但**里面也有 `url` 字段** |
| 去掉 `url` 的结构化版本 | **89** 字符 |

```python
# 续上文：这里假设 `e` 是上面捕获到的 ValidationError
import json

clean = [{k: v for k, v in err.items() if k != "url"} for err in e.errors()]
retry_prompt = (
    "你上次输出被拒绝，原因如下：\n"
    + json.dumps(clean, ensure_ascii=False)
)
# -> [{"type":"missing","loc":["email"],"msg":"Field required","input":{"name":"张三"}}]
```

> ⚠️ **只写 `json.dumps(e.errors())` 并没省多少**（192 → 142），
> 因为 `errors()` 里也带 `url`。**必须显式剔除**才真正省下来（→ 89，省 54%）。
> 这是实测数字 —— 我原来凭印象写的是"结构化就省 token"，是**不准确的**。

> 还有一个容易搞错的点：**模型返回的压根不是 JSON 时，抛的也是 `ValidationError`**
> （错误类型是 `json_invalid`），**不是 `JSONDecodeError`**。
> 所以 `except ValidationError` 这一条就够了，不用再单独捕 JSON 解析错。


> **这个"校验失败 → 错误喂回模型 → 重试"的闭环，是第 2 周的核心任务。**
> 你现在知道它的技术基础是什么了。

**dataclass 和 Pydantic 的区别**：

| | dataclass | Pydantic BaseModel |
|---|---|---|
| 运行时校验 | ❌ 不校验 | ✅ 严格校验 |
| 类型强制转换 | ❌ | ✅ 会尝试转换（`"42"` → `42`） |
| 从 JSON 解析 | 要手写 | `model_validate_json()` |
| 性能 | 更快 | 稍慢（有校验开销） |
| 用在哪 | 内部数据传递 | **API 边界、模型输出解析** |

## 常见坑

| 坑 | 说明 |
|---|---|
| 忘记写 `self` | `def greet():` 会报参数错误，必须 `def greet(self):` |
| 调用时传了 self | `user.greet()`，不要写 `user.greet(user)` |
| 以为类型注解会校验 | Python 运行时不检查，要 Pydantic |
| dataclass 带默认值的字段放前面 | `role: str = ""` 放前面，后面就不能有无默认值的字段 |
| 用可变对象做 dataclass 默认值 | 要写 `field(default_factory=list)` |
| 忘记 `__repr__` | 打印出来是内存地址，调试困难 |

<summary>参考答案</summary>

**1.**

```python
from dataclasses import dataclass

@dataclass
class Chunk:
    id: int
    text: str
    source: str
    tokens: int = 0

c = Chunk(id=0, text="第一段内容", source="doc.pdf", tokens=15)
print(c)
# Chunk(id=0, text='第一段内容', source='doc.pdf', tokens=15)
```

**2.**

```python
from typing import Literal
from pydantic import BaseModel, Field

class ChatMessage(BaseModel):
    role: Literal["system", "user", "assistant"]
    content: str = Field(..., min_length=1)

# 正常
m = ChatMessage(role="user", content="你好")
print(m)

# 错误 1：role 不合法
try:
    ChatMessage(role="bot", content="你好")
except Exception as e:
    print("role 错误：", e)

# 错误 2：content 为空
try:
    ChatMessage(role="user", content="")
except Exception as e:
    print("content 错误：", e)
```

两者的报错都会精确指出是哪个字段、什么问题。
**这就是为什么它能用来给大模型反馈**——错误信息本身就是可读的指令。

> 运行练习 2 需要先装 Pydantic：
> ```bash
> python3 -m venv .venv && source .venv/bin/activate
> pip install pydantic
> ```

**3.** 报错：`ValueError: mutable default <class 'list'> for field tags is not allowed: use default_factory`

原因和 [04 章](04-函数.md) 的可变默认参数**完全一样**：
`[]` 会被所有实例共享。

dataclass 直接禁止了这种写法，正确方式是：

```python
from dataclasses import dataclass, field

@dataclass
class Config:
    tags: list = field(default_factory=list)     # 每个实例创建新的空列表
    name: str = ""
```

> 注意这个设计：**dataclass 宁可报错也不让你写出 bug**。
> Pydantic 也是同样的哲学——用的时候你会感受到"严格"带来的好处。

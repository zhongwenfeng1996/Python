# 09 · 异步与并发（入门）

> **一句话总结**：调大模型是"等待型"任务，并发能省掉大量时间。
> 但 Python 的异步和 JS 有一个**致命差异**：忘记 `await` 不会报错。

---

## 1. 为什么需要异步

假设你要调用 3 个模型，每个耗时 2 秒：

```python
import time

def call_model(name):
    time.sleep(2)          # 模拟网络等待
    return f"{name} 的结果"

start = time.time()
results = [call_model(f"模型{i}") for i in range(3)]
print(f"耗时：{time.time() - start:.1f}s")      # 耗时：6.0s
```

**6 秒**里，CPU 几乎什么都没干——全在等网络。

用异步并发：

```python
import asyncio
import time

async def call_model(name):
    await asyncio.sleep(2)             # 模拟网络等待（注意是 asyncio.sleep）
    return f"{name} 的结果"

async def main():
    results = await asyncio.gather(
        call_model("模型0"),
        call_model("模型1"),
        call_model("模型2"),
    )
    print(results)

start = time.time()
asyncio.run(main())
print(f"耗时：{time.time() - start:.1f}s")      # 耗时：2.0s
```

**6 秒 → 2 秒**。这就是异步的价值。

> 在评估脚本里，这个差别可能是 30 分钟 vs 5 分钟。

## 2. 三个基本概念

```python
import asyncio

# 1. async def 定义一个"协程函数"
async def fetch(url):
    await asyncio.sleep(1)             # await 表示"这里会等待，可以先去做别的"
    return f"{url} 的内容"

# 2. 调用协程函数不会执行它，只创建一个协程对象
coro = fetch("http://example.com")     # ⚠️ 什么都没发生！
print(coro)                             # <coroutine object fetch at 0x...>

# 3. 必须用 asyncio.run() 或 await 驱动它
result = asyncio.run(fetch("http://example.com"))
print(result)
```

对比 JS：

```javascript
async function fetchData(url) {
  await sleep(1000);
  return "内容";
}
const p = fetchData("...");      // JS：调用即开始执行，返回 Promise
```

> **这是最大的心智差异**：
> - **JS**：`async` 函数调用后**立刻开始执行**，返回 `Promise`
> - **Python**：调用 `async def` 只是创建了一个**协程对象**，**没有任何代码被执行**
>
> Python 需要有人"驱动事件循环"（`asyncio.run()` 或 `await`）。
> 理解这一点，能避免后面 80% 的异步 bug。

## 3. ⚠️ 致命坑：忘记 await 不报错

```python
import asyncio

async def get_answer():
    await asyncio.sleep(0.1)
    return "答案"

async def main():
    # ❌ 忘记 await
    result = get_answer()
    print(result)          # <coroutine object get_answer at 0x10...>
    print(type(result))    # <class 'coroutine'>

asyncio.run(main())
```

**结果**：
- 不报错（可能只有一条 `RuntimeWarning: coroutine was never awaited`）
- 拿到的是一个协程对象，不是答案
- 后面用这个"结果"时才会以奇怪的方式失败

> **调试建议**：如果某个变量打印出来是 `<coroutine object ...>`，
> 100% 是忘了 `await`。
>
> 这是前端转 Python 在异步上栽的第一个跟头，也是最难查的之一——
> 因为**错误发生在很远的地方**，而不是忘记 await 的那一行。

## 4. `asyncio.gather`：并发执行

```python
import asyncio

async def call_model(name, delay):
    await asyncio.sleep(delay)
    return f"{name} 完成"

async def main():
    # 并发：总耗时 = 最慢的那个
    results = await asyncio.gather(
        call_model("A", 2),
        call_model("B", 1),
        call_model("C", 3),
    )
    print(results)         # ['A 完成', 'B 完成', 'C 完成']（顺序与传入一致）
    # 总耗时约 3 秒

asyncio.run(main())
```

**处理部分失败**：

```python
async def main():
    results = await asyncio.gather(
        call_model("A", 1),
        failing_task(),                    # 这个会抛异常
        call_model("C", 1),
        return_exceptions=True,            # 关键：异常作为结果返回，不中断其他任务
    )
    for r in results:
        if isinstance(r, Exception):
            print(f"有一个失败了：{r}")
        else:
            print(r)
```

**加超时**：

```python
async def main():
    try:
        result = await asyncio.wait_for(call_model("A", 10), timeout=3)
    except asyncio.TimeoutError:
        print("超过 3 秒，放弃")
```

## 5. 该用和不该用异步

**适合异步**（等待型 / IO 密集）：
- 调用大模型 API ✅
- 调用数据库 ✅
- 读写文件、下载文件 ✅
- 并发跑评估集 ✅

**不适合异步**（计算型 / CPU 密集）：
- 大量数据处理、矩阵运算 ❌（受 GIL 限制，不会变快）
- 图像处理 ❌
- 这类任务用 `multiprocessing`，或者干脆用 numpy 的向量化

> **前端直觉基本可用**：和 JS 一样，"等待用 async，计算不用"。
> 但 JS 的 `Promise.all` 会自动并发，而 Python 里你**必须显式用 `gather`**——
> 光写 `async def` 不会带来任何并发。

**另一个常见错误**：在异步代码里用阻塞调用

```python
import time

async def bad():
    time.sleep(2)          # ❌ 阻塞整个事件循环，其他任务全被卡住

async def good():
    await asyncio.sleep(2) # ✅ 让出控制权
```

发 HTTP 请求也一样：要用 `httpx.AsyncClient` 而不是 `requests`。

## 6. 在 AI 应用里：并发调模型

```python
import asyncio
import httpx

async def call_model(client, prompt, model="deepseek-chat"):
    response = await client.post(
        "/chat/completions",
        json={
            "model": model,
            "messages": [{"role": "user", "content": prompt}],
        },
    )
    return response.json()["choices"][0]["message"]["content"]

async def main():
    async with httpx.AsyncClient(
        base_url="https://api.deepseek.com/v1",
        headers={"Authorization": f"Bearer {API_KEY}"},
        timeout=60,
    ) as client:
        # 同一个问题问 5 个模型，对比效果
        models = ["deepseek-chat", "gpt-4o-mini", "qwen-plus"]
        tasks = [call_model(client, "用一句话解释 RAG", m) for m in models]
        results = await asyncio.gather(*tasks, return_exceptions=True)

        for model, result in zip(models, results):
            print(f"\n=== {model} ===")
            print(result)

asyncio.run(main())
```

**评估脚本里的典型用法**（第 5 周会写）：

```python
async def run_evaluation(questions, concurrency=5):
    """并发跑评估集，限制并发数避免打爆 API"""
    semaphore = asyncio.Semaphore(concurrency)

    async def limited(q):
        async with semaphore:              # 最多同时 5 个
            return await evaluate_one(q)

    return await asyncio.gather(*[limited(q) for q in questions])
```

> `Semaphore`（信号量）是**必须的**：不限并发会被 API 限流甚至封号。

## 常见坑

| 坑 | 说明 |
|---|---|
| 忘记 `await` | 不报错，但拿到的是协程对象 |
| `async def` 里用 `time.sleep` | 阻塞整个事件循环，要用 `asyncio.sleep` |
| 以为写了 async 就自动并发 | 必须用 `gather` 或 `create_task` 才并发 |
| 在 `async` 函数外直接调用 `await` | 报 `SyntaxError`，要用 `asyncio.run()` |
| 并发数不限制 | 被 API 限流，要用 `Semaphore` |
| 用 `requests` 做异步 | 它是同步库，要用 `httpx.AsyncClient` |

**1.**

```python
import asyncio
import time

async def wait_and_return(n):
    await asyncio.sleep(n)
    return n

async def main():
    start = time.time()
    results = await asyncio.gather(
        wait_and_return(1),
        wait_and_return(2),
        wait_and_return(3),
    )
    elapsed = time.time() - start
    print(f"结果：{results}")

asyncio.run(main())
```

**这个对比值得亲手做一遍**，体会才深。

**2.** 问题：`get_value()` **忘记 await**。

`value` 是一个协程对象，`value + 1` 会报
`TypeError: unsupported operand type(s) for +: 'coroutine' and 'int'`。

正确写法：

```python
async def main():
    value = await get_value()
    print(value + 1)          # 43
```

> 记住这个症状：**看到 `<coroutine object ...>` 就是忘了 await**。

**3.**

```python
import asyncio

async def ok(name):
    await asyncio.sleep(0.1)
    return f"{name} 成功"

async def fail():
    await asyncio.sleep(0.1)
    raise ValueError("故意失败")

async def main():
    results = await asyncio.gather(
        ok("任务A"),
        fail(),
        ok("任务C"),
        return_exceptions=True,
    )
    for i, r in enumerate(results):
        if isinstance(r, Exception):
            print(f"任务{i} 出错：{type(r).__name__}: {r}")
        else:
            print(f"任务{i}：{r}")

asyncio.run(main())
```

输出：

```
任务0：任务A 成功
任务1 出错：ValueError: 故意失败
任务2：任务C 成功
```

> **不加 `return_exceptions=True` 的话**，`gather` 会在第一个异常处
> 立刻抛出，其他任务的结果全部丢失。跑评估集时这个参数是必加的。

# 06 · 异常处理与文件读写

> **一句话总结**：调用外部服务（大模型 API）**一定会失败**，
> 异常处理不是"高级技巧"，而是 LLM 应用的日常。

---

## 1. 基本语法

```python
try:
    result = 10 / 0
except ZeroDivisionError as e:
    print(f"出错了：{e}")
finally:
    print("无论如何都会执行")
```

对比 JS：

```javascript
try {
  const result = 10 / 0;
} catch (e) {
  console.log(e.message);
} finally {
  console.log("无论如何都会执行");
}
```

| | JS | Python |
|---|---|---|
| 捕获 | `catch (e)` | `except Exception as e` |
| 错误信息 | `e.message` | `str(e)` 或直接 `{e}` |
| 抛出 | `throw new Error("x")` | `raise ValueError("x")` |
| 所有错误的基类 | `Error` | `Exception` |

**完整的四段结构**：

```python
try:
    data = fetch_data()
except ConnectionError as e:
    print(f"网络问题：{e}")
except ValueError as e:
    print(f"数据格式问题：{e}")
else:
    print("没有异常时执行")        # 和 try 里做的事分开，更清晰
finally:
    print("清理工作，总会执行")
```

## 2. 常见异常类型（记住这几个）

| 异常 | 什么时候出现 | 例子 |
|---|---|---|
| `ValueError` | 值不对 | `int("abc")` |
| `TypeError` | 类型不对 | `"1" + 1` |
| `KeyError` | 字典没有这个 key | `{"a":1}["b"]` |
| `IndexError` | 列表下标越界 | `[1,2][5]` |
| `ZeroDivisionError` | 除以零 | `1 / 0` |
| `FileNotFoundError` | 文件不存在 | `open("没有.txt")` |
| `AttributeError` | 对象没有这个属性 | `"abc".push(1)` |
| `json.JSONDecodeError` | JSON 解析失败 | `json.loads("不是json")` |

> **调试技巧**：看到异常名就知道大概是什么问题，不用读完整栈。
> `KeyError` → 字典取值少了；`IndexError` → 列表取多了。

---

## 3. 不要写裸 except（重要）

```python
# ❌ 千万不要这样写
try:
    result = call_model(prompt)
except:
    pass                    # 吞掉所有错误，包括 Ctrl+C！
```

**为什么糟糕**：
- 它会捕获 `KeyboardInterrupt`，你连 Ctrl+C 都停不下来
- 出错时没有任何信息，调试时完全不知道发生了什么
- 掩盖真正的 bug

```python
# ✅ 正确：捕获具体异常，并且一定要有输出
try:
    result = call_model(prompt)
except ValueError as e:
    print(f"参数错误：{e}")
    raise                                   # 处理不了就往上抛
except Exception as e:
    print(f"未预期的错误：{type(e).__name__}: {e}")
    raise
```

> **原则**：**能处理才捕获，处理不了就 `raise` 抛出去。**
> 安静的失败比崩溃更难排查。

---

## 4. 抛出异常

```python
def parse_usage(response):
    usage = response.get("usage")
    if usage is None:
        raise ValueError(f"响应缺少 usage 字段：{response}")
    return usage
```

自定义异常（简单版）：

```python
class ModelAPIError(Exception):
    """调用模型 API 失败"""
    pass

def call_model(prompt):
    if not prompt:
        raise ModelAPIError("prompt 不能为空")
```

> 自定义异常的价值：调用方可以精确捕获
> `except ModelAPIError`，而不是笼统地抓所有异常。

## 5. 文件读写

### 基本写法：一定要用 with

```python
# 写文件
with open("output.txt", "w", encoding="utf-8") as f:
    f.write("你好\n")

# 读文件
with open("output.txt", "r", encoding="utf-8") as f:
    content = f.read()

print(content)
```

> **`with` 是必须的**：它保证文件被正确关闭，即使中途出错。
> 相当于 JS 的 `try/finally`，但写起来更短。
>
> **`encoding="utf-8"` 也是必须的**：不写的话，Windows 上中文会乱码。

文件模式：
- `"r"` 读（默认）
- `"w"` 写（**会清空原内容**）
- `"a"` 追加
- `"rb"` / `"wb"` 二进制（处理 PDF、图片时用）

### 逐行读（大文件必用）

```python
with open("big.txt", "r", encoding="utf-8") as f:
    for line in f:
        print(line.strip())          # strip 去掉行尾换行符
```

### JSON 文件读写（最常用）

```python
import json

# 写
data = {"messages": [{"role": "user", "content": "你好"}]}
with open("history.json", "w", encoding="utf-8") as f:
    json.dump(data, f, ensure_ascii=False, indent=2)

# 读
with open("history.json", "r", encoding="utf-8") as f:
    loaded = json.load(f)

print(loaded["messages"][0]["content"])
```

> **`ensure_ascii=False` 很重要**：不写的话中文会变成 `\u4f60\u597d`。
> `indent=2` 让文件格式化，方便人看。

**对比字符串版本**：

```python
json.dumps(data)     # 字典  -> 字符串（s = string）
json.loads(text)     # 字符串 -> 字典
json.dump(data, f)   # 字典  -> 文件
json.load(f)         # 文件  -> 字典
```

> 记法：**带 `s` 的处理字符串，不带 `s` 的处理文件。**

### 用 pathlib 处理路径（比字符串拼接安全）

```python
from pathlib import Path

p = Path("data") / "history.json"       # 用 / 拼路径，跨平台安全
print(p)                                 # data/history.json

p.parent.mkdir(parents=True, exist_ok=True)   # 确保目录存在
print(p.exists())                             # 是否存在
print(p.suffix)                               # .json
print(p.stem)                                 # history

# 遍历目录下所有 txt
for file in Path(".").glob("*.txt"):
    print(file.name)
```

## 在 AI 应用里，它出现在哪

```python
# 1. API 调用失败重试（最常见的模式）
import time

def call_with_retry(messages, max_retries=3):
    last_error = None
    for attempt in range(max_retries):
        try:
            return call_model(messages)
        except Exception as e:
            last_error = e
            wait = 2 ** attempt              # 指数退避：1s, 2s, 4s
            print(f"第 {attempt+1} 次失败：{e}，{wait}s 后重试")
            time.sleep(wait)
    raise RuntimeError(f"{max_retries} 次重试全部失败") from last_error

# 2. 保存对话历史
def save_history(messages, path="history.json"):
    with open(path, "w", encoding="utf-8") as f:
        json.dump(messages, f, ensure_ascii=False, indent=2)

def load_history(path="history.json"):
    try:
        with open(path, "r", encoding="utf-8") as f:
            return json.load(f)
    except FileNotFoundError:
        return []                            # 文件不存在就返回空历史
    except json.JSONDecodeError as e:
        print(f"历史文件损坏：{e}")
        return []

# 3. 解析模型返回的 JSON（模型经常不听话）
def parse_model_json(text):
    cleaned = text.strip().removeprefix("```json").removesuffix("```").strip()
    try:
        return json.loads(cleaned)
    except json.JSONDecodeError as e:
        raise ValueError(f"模型没有返回合法 JSON：{text[:100]}") from e
```

> 第 3 个模式是第 2 周"结构化输出"的核心——
> **模型会返回不合法的 JSON，你必须处理这种情况。**

## 常见坑

| 坑 | 说明 |
|---|---|
| `except: pass` | 吞掉所有错误，包括 Ctrl+C，调试噩梦 |
| 忘记 `encoding="utf-8"` | 中文乱码 |
| `open("a.txt", "w")` | 会**清空**原文件，追加要用 `"a"` |
| 忘记 `with` | 文件可能不关闭，数据可能没写入 |
| `json.dump` 没有 `ensure_ascii=False` | 中文变成 `\uXXXX` |
| `json.dumps` 和 `json.dump` 混用 | 带 `s` 处理字符串 |

## 练习

**1.** 写一个函数 `safe_read_json(path)`：
文件不存在返回 `None`，内容不是合法 JSON 也返回 `None`，正常则返回解析结果。

**2.** 写一个函数 `call_with_retry(func, max_retries=3)`：
调用 `func()`，失败时打印错误并重试，最多 3 次，全失败则抛出最后一次的异常。

**3.** 下面代码有什么问题？

```python
def get_content(response):
    try:
        return response["choices"][0]["message"]["content"]
    except:
        return ""
```

**1.**

```python
import json

def safe_read_json(path):
    try:
        with open(path, "r", encoding="utf-8") as f:
            return json.load(f)
    except FileNotFoundError:
        print(f"文件不存在：{path}")
        return None
    except json.JSONDecodeError as e:
        print(f"JSON 格式错误：{e}")
        return None
```

关键点：捕获的是**具体的异常**，而且每种情况都有明确输出。
这样出问题时你能立刻知道是哪一类。

**2.**

```python
import time

def call_with_retry(func, max_retries=3):
    last_error = None
    for attempt in range(max_retries):
        try:
            return func()
        except Exception as e:
            last_error = e
            print(f"第 {attempt + 1} 次失败：{e}")
            time.sleep(2 ** attempt)          # 1s, 2s, 4s
    raise RuntimeError(f"重试 {max_retries} 次全部失败") from last_error
```

用法：

```python
result = call_with_retry(lambda: call_model(messages))
```

`from last_error` 会保留原始异常链，traceback 里能看到**根本原因**，
这在调试 API 问题时非常有用。

**3.** 两个问题：

1. **裸 `except:`** —— 会捕获所有异常，包括 `KeyboardInterrupt`
   （Ctrl+C 都停不下来）和 `MemoryError`，而且静默返回 `""`，
   出错时你完全不知道原因。

2. **无法区分"结构缺失"和"内容为空"** —— 返回 `""` 会让调用方以为
   是模型返回了空内容，而实际可能是响应格式变了。

改进写法：

```python
def get_content(response):
    choices = response.get("choices") or []
    if not choices:
        raise ValueError(f"响应没有 choices：{response}")
    message = choices[0].get("message") or {}
    content = message.get("content")
    if content is None:
        raise ValueError(f"响应没有 content：{choices[0]}")
    return content
```

> 看起来啰嗦，但**生产代码必须这样写**。
> 因为 API 出错时，你需要的是一条明确的错误信息，
> 而不是一个安静的、看起来很正常的空字符串。

# 01 · 变量与数据类型

> **一句话总结**：Python 不需要声明类型，写下名字就是变量；但"可变"与"不可变"的区别会一直影响到你写 AI 应用。

---

## 1. 变量：不需要 let / const

```python
count = 0
name = "Alice"
price = 9.9
is_active = True
nothing = None
```

对比 JS：

```javascript
let count = 0;
const name = "Alice";
let price = 9.9;
let isActive = true;
let nothing = null;
```

Python 里**没有 `let` / `const` / `var`**，直接写 `名字 = 值` 就是赋值。

### 命名习惯（很重要，代码风格会影响别人对你的判断）

```python
user_name = "Alice"        # 变量和函数：小写 + 下划线（snake_case）
MAX_TOKENS = 2048          # 常量：全大写（语言不强制，是约定）
class UserProfile: ...     # 类名：大驼峰（PascalCase）
```

> **前端注意**：JS 习惯 `userName`（小驼峰），Python 习惯 `user_name`（下划线）。
> 写 Python 时请入乡随俗，混用会让代码看起来很业余。

## 2. 五种基本类型

```python
count = 42            # int      整数
price = 9.99          # float    小数
name = "Alice"        # str      字符串
is_active = True      # bool     布尔（首字母大写！）
nothing = None        # NoneType 空值（首字母大写！）
```

查看类型：

```python
print(type(count))     # <class 'int'>
print(type(name))      # <class 'str'>
```

> **前端注意**：`True` / `False` / `None` 都是**首字母大写**。
> 写成 `true` / `false` / `null` 会报 `NameError`。这是最高频的低级错误。

## 3. 类型转换

| 目标 | 写法 | JS 对应 |
|---|---|---|
| 转整数 | `int("42")` | `parseInt("42")` |
| 转小数 | `float("9.9")` | `parseFloat("9.9")` |
| 转字符串 | `str(42)` | `String(42)` |
| 转布尔 | `bool(1)` | `Boolean(1)` |

```python
age_text = "25"
age = int(age_text)          # 字符串 -> 整数
print(age + 1)               # 26

print(str(42) + "岁")        # "42岁"
# print(42 + "岁")           # ❌ TypeError：Python 不会自动转换
```

> **前端注意**：JS 的 `"1" + 2` 得到 `"12"`（隐式转换）。
> Python 会直接报 `TypeError`。**这其实是好事**——错误早暴露比晚暴露好。

转换失败会报错：

```python
int("abc")     # ❌ ValueError: invalid literal for int() with base 10: 'abc'
```

## 4. 数字运算

```python
print(7 / 2)      # 3.5     ← 除法总是返回 float（重要！）
print(7 // 2)     # 3       ← 整除，向下取整
print(7 % 2)      # 1       ← 取余
print(2 ** 10)    # 1024    ← 幂运算（JS 是 Math.pow 或 2**10）
```

> **前端注意**：JS 里 `7 / 2` 也是 3.5，这一点相同。
> 但 Python 里**整数除法想得到整数必须用 `//`**，这在分页计算时会用到。

## 5. 真值判断（falsy 值）

```python
# 这些值在 if 判断里都算"假"
if not 0: print("0 是假")
if not "": print("空字符串是假")
if not []: print("空列表是假")
if not {}: print("空字典是假")
if not None: print("None 是假")
```

这和 JS 的 falsy 规则很像（`0` / `""` / `null` / `undefined` / `NaN`），
但有一个关键差异：

```python
print(bool([]))    # False   ← Python：空列表是假
```

```javascript
Boolean([])        // true    ← JS：空数组是真！
```

> **前端重点坑**：JS 里 `[]` 和 `{}` 都是**真值**，Python 里都是**假值**。
> 这会影响你写 `if messages:` 这种判断——Python 里它会自动判断"列表非空"。

这个特性有个很实用的用法：

```python
messages = []
if messages:
    print("有历史记录")
else:
    print("这是第一轮对话")     # ← 会走这里
```

## 6. 可变与不可变（本节最重要）

```python
# 不可变：改了就是新建一个对象
a = "hello"
b = a
b = b + " world"
print(a)      # hello      ← a 没变

# 可变：改的是同一个对象
x = [1, 2, 3]
y = x
y.append(4)
print(x)      # [1, 2, 3, 4]   ← x 也变了！
```

**不可变类型**：`int` `float` `str` `bool` `None` `tuple`
**可变类型**：`list` `dict` `set`

```python
# 要真正复制一个列表，必须显式复制
x = [1, 2, 3]
y = x[:]           # 切片复制（最常用）
y.append(4)
print(x)           # [1, 2, 3]   ← x 没变
```

> **为什么这很重要**：这个特性是第 05 章"可变默认参数 bug"的根源，
> 也是 LLM 应用里"对话历史被意外修改"这类诡异 bug 的根源。

## 在 AI 应用里，它出现在哪

### 先搞清楚：`response` 是什么？

后面几章的例子里会反复出现 `response.get("usage")`、`response["choices"][0]`，
但**这个 `response` 不是你凭空写的变量**，它是"调用模型 API 之后拿回来的那个东西"。

先看完整的三步，缺一步你都看不懂那些例子：

```python
import json
import urllib.request

# ---- 第 1 步：你发出去的请求 ----
# 这是一个普通的字典，通过 json.dumps 转成 JSON 字符串发出去
data = {
    "model": "deepseek-chat",
    "messages": [{"role": "user", "content": "用一句话解释什么是向量"}],
}
body = json.dumps(data, ensure_ascii=False).encode("utf-8")

request = urllib.request.Request(
    "https://api.deepseek.com/v1/chat/completions",
    data=body,
    headers={"Content-Type": "application/json",
             "Authorization": "Bearer 你的key"},
)

# ---- 第 2 步：拿到响应（response 在这里诞生）----
with urllib.request.urlopen(request, timeout=60) as response:
    raw = response.read().decode("utf-8")     # raw 是一段 JSON 字符串

# ---- 第 3 步：把 JSON 字符串变成 Python 字典 ----
# ★ 从这一行之后，response 这个名字才开始代表"一个嵌套的字典"
response = json.loads(raw)
```

**关键点**：`urlopen` 返回的 `response` 是"HTTP 响应对象"，
而 `json.loads` 返回的 `response` 是"Python 字典"。
上面的代码里第二个赋值把第一个**覆盖**了 —— 这是教程里常见的省事写法，
但它正是新手最容易迷惑的地方：**同一个名字，前后是两个完全不同的东西**。

所以后面所有例子里说的 `response`，都指**第 3 步那个字典**。

### 这个字典长什么样（真实响应，不是编的）

```json
{
  "id": "mock-completion",
  "object": "chat.completion",
  "model": "deepseek-chat",
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "向量就是带方向和大小的量，可以理解成一支箭头。"
      },
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 11,
    "completion_tokens": 23,
    "total_tokens": 34
  }
}
```

> 想自己看一眼真实响应：跑 `python3 week01/show_response.py`
> （配合 `mock_server.py` 不需要 Key）。**看到原文，比看任何解释都清楚。**

### 怎么一层层把它取出来

这段是本章最重要的一段 —— 以后你会写几十遍：

```python
response["choices"]                 # list（一个列表）
response["choices"][0]              # dict（列表的第 0 项，是字典）
response["choices"][0]["message"]   # dict（嵌套字典）
response["choices"][0]["message"]["content"]   # str ← 模型的回答在这里

response["usage"]["prompt_tokens"]        # int ← 输入用了多少 token
response["usage"]["completion_tokens"]    # int ← 输出用了多少 token
```

看着乱，其实有规律：**`[]` 里是数字就是在取列表，是字符串就是在取字典的键。**

- `response["choices"]` → `"choices"` 是字符串 → 取字典的键 → 得到一个**列表**
- `[0]` → 数字 → 取列表的第 0 项 → 得到一个**字典**
- `["message"]` → 字符串 → 取字典的键 → 又得到一个**字典**
- `["content"]` → 字符串 → 取字典的键 → 得到一个**字符串** ✅

**为什么是列表？** 因为模型可以一次生成多个候选回答（`n` 参数），
所以 `choices` 是列表，哪怕你只要一个也得写 `[0]`。
这是初学者最常问的"为什么这么绕"的答案。

### 现在再看本章的代码，它们才有意义

```python
# 1. 模型参数配置 —— 全是变量和类型
temperature = 0.7        # float
max_tokens = 2048        # int
is_streaming = True      # bool
model_name = "deepseek-chat"   # str

# 2. 空值判断 —— response 这个字典里可能没有 "usage" 这个键
usage = response.get("usage")       # 键不存在时返回 None，而不是报错
if usage is None:
    print("这个接口没有返回 token 统计")

# 3. 真值判断的典型用法
text = response["choices"][0]["message"]["content"]
if not text:                       # 空字符串
    print("模型返回了空内容，需要重试")     # ← 生产代码里非常常见

# 4. 可变对象的坑
history = [{"role": "user", "content": "你好"}]
backup = history              # ❌ 这不是复制！
backup.append({"role": "assistant", "content": "你好"})
print(len(history))           # 2 —— history 也被改了
```

> **为什么第 2 条用 `.get()`，第 3 条用 `["..."]`？**
> 因为 `usage` 这个键**可能不存在**（不是所有接口都返回它），
> 而 `choices` 一定有。键可能不存在就用 `.get()`（取不到返回 `None`，安全），
> 一定有就用 `[...]`（取不到会 `KeyError`，但那种情况本来就该报错）。
>
> 这个判断在本章练习第 3 题会展开 —— 而且答案比你想的复杂。

## 常见坑

| 坑 | 错误写法 | 正确写法 |
|---|---|---|
| 布尔/空值大小写 | `true` `false` `null` | `True` `False` `None` |
| 字符串与数字相加 | `"1" + 2` | `"1" + str(2)` |
| 以为 `/` 返回整数 | `7 / 2` 得到 3.5 | `7 // 2` 得到 3 |
| 以为空列表是真值 | `if []:` | Python 里是假值 |
| 赋值等于复制 | `b = a` | `b = a[:]` 或 `copy.deepcopy(a)` |

**3.** 下面这段判断在生产代码里可能有问题，为什么？

**先说明这段代码的上下文**（不然你没法判断 —— 这也是读别人代码时的第一反应）：

```python
# 完整的上下文：这是一个封装好的"调一次模型"函数
import json
import urllib.request

def call_model(messages, api_key):
    """调一次模型，返回解析好的响应字典。"""
    data = {"model": "deepseek-chat", "messages": messages}
    body = json.dumps(data, ensure_ascii=False).encode("utf-8")
    request = urllib.request.Request(
        "https://api.deepseek.com/v1/chat/completions",
        data=body,
        headers={"Content-Type": "application/json",
                 "Authorization": f"Bearer {api_key}"},
    )
    with urllib.request.urlopen(request, timeout=60) as http_response:
        raw = http_response.read().decode("utf-8")
    return json.loads(raw)          # ← 返回的是嵌套字典

# ↓↓↓ 要审的就是这三行 ↓↓↓
response = call_model([{"role": "user", "content": "你好"}], "你的key")
usage = response.get("usage")
if not usage:
    print("没有 token 统计")
```

**判断这段代码，你需要先知道两件事：**

1. `response` 是 `call_model()` 的返回值，也就是**第 3 步那个嵌套字典**
   （见本章前面的「先搞清楚：`response` 是什么？」）。
2. `response.get("usage")` 的取值可能是：
   - `None` —— 键不存在（接口没返回这个字段）
   - `{}` —— 键存在但是空字典
   - `{"prompt_tokens": 0, "completion_tokens": 0}` —— 结构完整但数值是 0
   - `{"prompt_tokens": 11, "completion_tokens": 23, ...}` —— 正常情况

**问题**：`if not usage` 会把这四种情况**各自**判成什么？哪种判断是错的？
改成 `if usage is None` 会更好吗，还是引入新问题？

> 提示：注意区分"假值"和"空值"。`not {}` 是 `True`，但 `not {"a": 0}` 是 `False`
> —— 非空字典一律是真值，**哪怕里面的数值都是 0**。

**3.** 有隐患，但**不是**"该用 `is None` 却用了 `not`"这么简单。分三层看：

**第一层：`not usage` 会把 `{}` 误判成"没有统计"。**
`not` 判断的是"真假"，而 `None` 和 `{}` 都是假值。想区分它们，得显式比较。

**第二层：但把 `if not usage` 改成 `if usage is None` 会更糟。**
因为 `usage` 真的等于 `{}` 时，`is None` 返回 `False`，代码会**继续往下走**，
然后执行 `usage["prompt_tokens"]` → `KeyError` 直接崩。
原写法虽然分类不精确，但至少不会崩 —— 这个"修正"把安全代码改成了会崩的代码。

**第三层：还有一种更隐蔽的情况答案漏了 —— 结构完整但数值全为 0。**
有些兼容端点"实现了" usage 却懒得填数字：

```python
usage = {"prompt_tokens": 0, "completion_tokens": 0}
```

这时 `not usage` 是 `False`、`is None` 也是 `False`，两种写法都认为"有统计"，
于是你的成本看板显示 **$0.0000** —— 比"没有统计"更误导人。

**所以真正要判断的是"有没有可用的数值"，而不是"是不是 None"：**

```python
def usable_usage(raw):
    """从 API 返回的 usage 里取出可用的 token 数；取不到就返回 None。"""
    if not isinstance(raw, dict):       # None、字符串、别的类型，一律当没有
        return None
    # 不同厂商的字段名不一样，两种都试
    prompt = raw.get("prompt_tokens") or raw.get("input_tokens") or 0
    completion = raw.get("completion_tokens") or raw.get("output_tokens") or 0
    if not prompt and not completion:   # 全 0（或字段缺失）也算"没有"
        return None
    return int(prompt), int(completion)

tokens = usable_usage(response.get("usage"))
if tokens is None:
    print("接口没有返回可用的 token 统计，改用估算")
    in_tokens, out_tokens = estimate_tokens(messages), estimate_tokens(answer)
else:
    in_tokens, out_tokens = tokens
```

**判断原则（三条，别只记第一条）：**

| 想表达的意思 | 写法 | 反例 |
|---|---|---|
| 是不是 `None` | `x is None` | `if not x` 会把 `{}` `0` `""` 也算进去 |
| 是不是空容器 | `if not x` | 但 `0` 和 `""` 也会命中，语义比你想的宽 |
| **字段有没有可用数值** | `x.get(k) or 0` + 判断总和 | 只判 `None` 会漏掉"全 0"这种情况 |

> **这道题在仓库里有真实对照。** 上面那段 `usable_usage` 不是凭空写的，
> 它对应 [项目一的 `cost.py`](../../projects/project1-stream-chat/backend/cost.py)
> 里的 `usage_from_api()`，以及 [`week01/chat.py`](../../week01/chat.py) 第 282–296 行
> 的"取不到 usage 就回退到估算"。
>
> **建议你现在就去读那两处**（一共 20 行），看真实生产代码是怎么处理这个问题的 ——
> 练习题的价值不在于答对，而在于你回头能在真代码里认出它。

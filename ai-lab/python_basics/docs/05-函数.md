# 05 · 函数

> **一句话总结**：函数的语法比 JS 简单，但有一个**必须记住的坑**——
> 可变对象做默认参数会让所有调用共享同一个值。

---

## 1. 定义与调用

```python
def greet(name):
    return f"你好，{name}"

message = greet("小明")
print(message)          # 你好，小明
```

对比 JS：

```javascript
function greet(name) {
  return `你好，${name}`;
}
const greet2 = (name) => `你好，${name}`;   // Python 没有箭头函数
```

三个差异：

| | JS | Python |
|---|---|---|
| 定义 | `function f() {}` | `def f():` |
| 代码块 | `{ }` | 缩进 |
| 没有返回值 | 返回 `undefined` | 返回 `None` |

```python
def do_nothing():
    pass            # pass 表示"什么都不做"，占位用

result = do_nothing()
print(result)       # None
```

## 2. 返回多个值（Python 独有，很好用）

```python
def parse_response(response):
    content = response["choices"][0]["message"]["content"]
    tokens = response["usage"]["completion_tokens"]
    return content, tokens          # 实际返回一个元组

text, token_count = parse_response(resp)     # 解包
print(text, token_count)
```

对比 JS：要返回对象 `return { content, tokens }`。Python 可以直接返回元组。

## 3. 参数：默认值、关键字参数

```python
def chunk_text(text, chunk_size=200, overlap=50):
    ...

# 位置参数
chunk_text("长文本...", 300, 60)

# 关键字参数（更清晰，推荐）
chunk_text("长文本...", chunk_size=300, overlap=60)

# 只传一部分
chunk_text("长文本...", overlap=80)
```

> **关键字参数是 Python 的一大优势**。对比 JS 里常见的
> `chunkText(text, { chunkSize: 300, overlap: 60 })`，
> Python 不需要传对象，调用处照样清晰。

## 4. ⚠️ 最大的坑：可变默认参数

**这段代码有问题，先看你能不能发现**：

```python
def add_message(msg, messages=[]):
    messages.append(msg)
    return messages

print(add_message("第一条"))    # ['第一条']
print(add_message("第二条"))    # ['第一条', '第二条']  ← 咦？
print(add_message("第三条"))    # ['第一条', '第二条', '第三条']
```

**为什么？** Python 的默认参数**只在函数定义时求值一次**，
之后所有调用共享同一个列表对象。

正确写法：

```python
def add_message(msg, messages=None):
    if messages is None:
        messages = []
    messages.append(msg)
    return messages

print(add_message("第一条"))    # ['第一条']
print(add_message("第二条"))    # ['第二条']      ✅
```

> **规则**：默认参数**永远不要用可变对象**（`[]`、`{}`、`set()`）。
> 用 `None` 作为默认值，在函数体内再创建。
>
> 这个 bug 在 LLM 应用里特别危险——它会让不同用户的对话历史串在一起。

## 5. `*args` 和 `**kwargs`（够用版）

```python
# *args：接收任意数量的位置参数，打包成元组
def sum_all(*numbers):
    return sum(numbers)

print(sum_all(1, 2, 3))         # 6

# **kwargs：接收任意数量的关键字参数，打包成字典
def call_model(**options):
    print(options)

call_model(model="gpt-4o", temperature=0.7)
# {'model': 'gpt-4o', 'temperature': 0.7}
```

**最常见的实际用法**——给函数透传参数：

```python
def call_model(messages, **options):
    payload = {"messages": messages}
    payload.update(options)          # 把额外参数合并进去
    return request(payload)

call_model(messages, temperature=0.7, max_tokens=2048)
```

## 7. 作用域速查

```python
GLOBAL_CONFIG = {"model": "deepseek-chat"}      # 全局，函数内可读

def show():
    print(GLOBAL_CONFIG["model"])               # ✅ 读取没问题

def change():
    GLOBAL_CONFIG["model"] = "gpt-4o"           # ✅ 修改字典内容没问题！
    # 注意：这不是重新赋值，是修改对象的内部状态

def replace():
    global GLOBAL_CONFIG
    GLOBAL_CONFIG = {}                          # ⚠️ 这才是重新赋值，需要 global
```

> 容易混淆的点：**修改可变对象的"内容"不需要 `global`，给变量重新赋值才需要。**

## 8. 在 AI 应用里，函数是怎么组织的

一个典型的 LLM 应用会被拆成这些函数：

```python
def load_config() -> dict:
    """读环境变量和配置"""

def build_messages(question, context) -> list:
    """把问题和检索到的资料拼成 messages"""

def call_model(messages, **options) -> dict:
    """调用模型 API"""

def parse_response(response) -> str:
    """从响应里提取文本"""

def estimate_tokens(text) -> int:
    """估算 token 数（API 没返回 usage 时用）"""

def calc_cost(model, in_tokens, out_tokens) -> float:
    """计算成本"""

def stream_and_print(response) -> str:
    """边收流式响应边打印，返回完整文本"""
```

**这就是 [`week01/chat.py`](../../week01/chat.py) 的组织方式。**
你现在应该能读懂它的每个函数在做什么了。

## 常见坑

| 坑 | 说明 |
|---|---|
| `def f(items=[])` | **可变默认参数**，所有调用共享同一个列表 |
| 忘记 `return` | 函数返回 `None`，不是 `undefined` |
| 函数内给全局变量赋值 | 报 `UnboundLocalError`，要么用参数，要么 `global` |
| 以为函数内修改字典需要 global | **不需要**，只有重新赋值才需要 |
| `pass` 忘记写 | 空函数体不能留空，要写 `pass` |

<summary>参考答案</summary>

**1.**

```python
def chunk_text(text, chunk_size=100, overlap=20):
    chunks = []
    start = 0
    while start < len(text):
        end = start + chunk_size
        chunks.append(text[start:end])
        start = end - overlap          # 注意：回退 overlap，避免死循环
    return chunks

print(chunk_text("a" * 250))
```

> 注意 `overlap` 必须小于 `chunk_size`，否则 `start` 不会前进，会死循环。
> 可以加一句防御：`overlap = min(overlap, chunk_size - 1)`。

**2.**

```python
PRICES = {
    "gpt-4o-mini": (0.15, 0.60),
    "deepseek-chat": (0.27, 1.10),
}

def calc_cost(model, in_tokens, out_tokens):
    price_in, price_out = PRICES.get(model, (0.5, 1.5))
    return in_tokens / 1_000_000 * price_in + out_tokens / 1_000_000 * price_out

print(calc_cost("deepseek-chat", 1000, 500))     # 约 0.00082
```

小技巧：`1_000_000` 里的下划线只是给人看的，Python 会忽略它。

**3.** 问题就是**可变默认参数**。

`history=[]` 只在定义时创建一次，所有调用共享同一个列表。
连续调用会让数字不断累加，而不是每次从零开始。

```python
def record_usage(tokens, history=None):
    if history is None:
        history = []
    history.append(tokens)
    return sum(history)

print(record_usage(100))    # 100
print(record_usage(200))    # 200      ✅ 不会累加
print(record_usage(300))    # 300
```

> 如果确实需要"跨调用累积"，就应该用一个类或明确的全局状态，
> 而不是靠默认参数——那样写出来的人自己都会困惑。
